Подробное руководство по проекту Flask

Учебное объяснение проекта на уровне начинающего пользователя и разработчика

1. Что это за проект

Этот проект представляет собой веб-приложение на языке Python с использованием фреймворка Flask. По смыслу проект состоит из двух частей:

  1. Публичный сайт предприятия «Радиозавод “Вектор”». На нем есть страницы о компании, продукции, услугах, контактах и вакансиях.
  2. Внутренняя система кадрового учета. Внутри нее администратор может работать с отделами, должностями, сотрудниками и пользователями.

То есть для обычного посетителя это сайт завода, а для администратора внутри сайта есть служебный модуль кадрового учета.

2. Базовые понятия, без которых трудно понять проект

2.1 Что такое Python

Python — это язык программирования. На нем пишут инструкции, которые выполняет компьютер. В этом проекте Python используется для серверной части: он обрабатывает запросы пользователя, работает с базой данных и выбирает, какую HTML-страницу показать.

2.2 Что такое Flask

Flask — это веб-фреймворк. Фреймворк — это готовый набор инструментов для создания сайта или веб-приложения. Flask берет на себя маршрутизацию, работу с запросами, шаблонами, формами и расширениями.

2.3 Что такое веб-приложение

Веб-приложение — это программа, которая работает на сервере и открывается через браузер. Пользователь заходит на адрес сайта, браузер отправляет HTTP-запрос, сервер обрабатывает его и возвращает HTML-страницу.

2.4 Что такое HTML

HTML — это язык разметки страниц. Он описывает структуру сайта: заголовки, абзацы, таблицы, формы, ссылки, кнопки.

2.5 Что такое CSS

CSS — это язык оформления. Он не создает структуру, а отвечает за внешний вид: цвета, отступы, размеры, расположение блоков, шрифты.

2.6 Что такое шаблон

Шаблон — это HTML-файл, в котором могут быть специальные вставки Jinja2. Flask подставляет в эти вставки данные из Python-кода. Например, список сотрудников или имя текущего пользователя.

2.7 Что такое Jinja2

Jinja2 — это шаблонизатор. Он позволяет внутри HTML использовать конструкции вида {{ variable }} и {% for item in items %}. Таким образом одна страница может отображать разные данные.

2.8 Что такое маршрут

Маршрут (route) — это адрес сайта и функция, которая обслуживает этот адрес. Например, маршрут /about ведет на страницу «О компании».

2.9 Что такое Blueprint

Blueprint во Flask — это способ разделить большой проект на части. В этом проекте есть три группы маршрутов:

  • auth — вход, выход, регистрация;
  • main — публичные страницы;
  • admin — внутренний кадровый раздел.

2.10 Что такое база данных

База данных — это место хранения информации. В проекте используется SQLite. Это файловая база данных. Все данные лежат в файле instance/job.db.

2.11 Что такое ORM

ORM — это способ работать с таблицами базы данных как с обычными Python-классами. В проекте используется SQLAlchemy. Благодаря ей не нужно вручную писать SQL-запросы в большинстве случаев.

2.12 Что такое модель

Модель — это Python-класс, который описывает таблицу в базе данных. Например:

  • User — таблица пользователей;
  • Department — таблица отделов;
  • Position — таблица должностей;
  • Employee — таблица сотрудников.

2.13 Что такое форма

Форма — это набор полей ввода на странице. Пользователь вводит данные, сервер их проверяет и сохраняет. В проекте формы реализованы через Flask-WTF и WTForms.

2.14 Что такое аутентификация и авторизация

  • Аутентификация — это проверка личности пользователя. Пример: вход по логину и паролю.
  • Авторизация — это проверка прав. Пример: можно ли пользователю открыть страницу админки.

2.15 Что такое CSRF-защита

CSRF — это защита от поддельных запросов. Она нужна, чтобы злоумышленник не смог заставить авторизованного пользователя отправить скрытый POST-запрос с другого сайта.

4. Как работает приложение в целом

  1. Пользователь открывает страницу сайта в браузере.
  2. Браузер отправляет запрос на сервер Flask.
  3. Flask находит нужный маршрут.
  4. Функция маршрута, написанная на Python, выполняет логику.
  5. Если нужно, функция читает или изменяет данные в базе.
  6. После этого Flask возвращает HTML-шаблон с подставленными данными.
  7. Браузер показывает пользователю готовую страницу.

5. Подробное объяснение файла app.py

Файл app.py — это сердце проекта. Он запускает все приложение.

5.1 Импорт модулей

Сначала подключаются нужные библиотеки и собственные модули проекта. Это обычная практика: перед использованием чего-либо его надо импортировать.

5.2 Создание объекта Flask

app = Flask(__name__) создает само веб-приложение.

5.3 Конфигурация

  • SQLALCHEMY_DATABASE_URI — путь к базе данных SQLite.
  • REMEMBER_COOKIE_DURATION — сколько хранится cookie режима «запомнить меня».
  • SECRET_KEY — секретный ключ приложения. Нужен для сессий и CSRF.
  • SQLALCHEMY_TRACK_MODIFICATIONS — отключает лишний служебный механизм SQLAlchemy.

5.4 Подключение расширений

  • db.init_app(app) — подключает базу данных к Flask.
  • Bootstrap5(app) — дает возможность использовать Bootstrap.
  • CSRFProtect(app) — включает CSRF-защиту форм.

5.5 Настройка LoginManager

LoginManager отвечает за авторизацию пользователя.

  • login_view = 'auth.login' — если доступ закрыт, пользователя отправят на страницу входа.
  • login_message — текст, который покажется перед перенаправлением.

5.6 Функция load_user(user_id)

Эта функция нужна Flask-Login. Когда пользователь уже вошел в систему, Flask-Login хранит его ID и при каждом запросе вызывает load_user, чтобы получить объект пользователя из базы.

5.7 Регистрация blueprints

Здесь подключаются все разделы проекта:

  • /auth — маршруты авторизации;
  • /admin — кадровый учет;
  • / — основной публичный сайт.

5.8 Обработчики ошибок

  • forbidden(error) — возвращает страницу 403.
  • not_found(error) — возвращает страницу 404.
  • internal_error(error) — при ошибке 500 откатывает транзакцию базы, пишет ошибку в лог и показывает страницу 500.

5.9 Функция init_database()

Она создает таблицы в базе данных, если они еще не созданы. Для этого используется db.create_all().

5.10 Блок запуска приложения

Если файл запускается напрямую, берутся параметры хоста и порта, определяется режим debug и запускается сервер Flask.

6. Подробное объяснение моделей из models.py

6.1 Объект db

db = SQLAlchemy() — главный объект, через который создаются модели и выполняются операции с базой.

6.2 Модель User

Описывает пользователя сайта.

  • id — уникальный идентификатор;
  • username — логин;
  • password — хэш пароля;
  • is_admin — признак администратора;
  • has_completed_survey — дополнительное логическое поле, сейчас в проекте не используется активно.

Класс наследуется от UserMixin, чтобы Flask-Login мог с ним работать.

6.3 Модель Department

Описывает отдел организации. Эта модель поддерживает иерархию, то есть отдел может иметь родительский отдел.

  • name — название отдела;
  • parent_id — идентификатор родительского отдела;
  • sub_departments — список дочерних отделов;
  • positions — должности, относящиеся к отделу.

Свойство all_employees

Это вычисляемое свойство. Оно не хранится в таблице, а собирает список активных сотрудников, проходя по всем должностям отдела.

6.4 Модель Position

Описывает должность.

  • title — название должности;
  • department_id — отдел, к которому относится должность;
  • employees — сотрудники на этой должности.

6.5 Модель Employee

Описывает сотрудника.

  • last_name, first_name, middle_name — ФИО;
  • email и phone — контакты;
  • hire_date — дата;
  • is_active — активен ли сотрудник;
  • position_id — должность.

Свойство full_name

Собирает полное имя в одну строку для удобного вывода в шаблонах.

6.6 Модель ActiveVacancy

Описывает опубликованную вакансию. По сути это связь с должностью: если запись существует, значит должность опубликована как вакансия.

7. Подробное объяснение форм из forms.py

7.1 RegisterForm

Форма регистрации пользователя.

  • Проверяет длину логина.
  • Проверяет пароль по регулярному выражению.
  • Проверяет совпадение пароля и подтверждения.

7.2 LoginForm

Форма входа. Содержит логин, пароль и чекбокс «Запомнить меня».

7.3 DepartmentForm

Форма создания и редактирования отдела.

7.4 PositionForm

Форма создания и редактирования должности.

7.5 EmployeeForm

Форма создания и редактирования сотрудника.

Важно: формы не просто собирают данные, но и валидируют их. Это значит, что приложение не примет пустой обязательный ввод или неверный email.

8. Подробное объяснение auth.py

8.1 Blueprint auth

Это отдельный блок маршрутов для авторизации.

8.2 Функция register()

Логика функции:

  1. Создается форма регистрации.
  2. Если форма отправлена и прошла проверку, приложение ищет пользователя с таким логином.
  3. Если логин уже занят, показывается сообщение об ошибке.
  4. Если логин свободен, пароль хэшируется.
  5. Создается новый объект User.
  6. Пользователь сохраняется в базе.
  7. После успешной регистрации выполняется переход на страницу входа.

8.3 Функция login()

Логика функции:

  1. Создается форма входа.
  2. По логину находится пользователь.
  3. Проверяется пароль через check_password_hash.
  4. Если все верно, вызывается login_user.
  5. Если данные неверны, выводится сообщение об ошибке.

8.4 Функция logout()

Вызывает logout_user(), удаляет активную сессию и отправляет пользователя на страницу входа.

9. Подробное объяснение main.py

9.1 Blueprint main

Это набор публичных маршрутов сайта предприятия.

9.2 Функции home(), about(), contact(), products(), services()

Каждая из этих функций делает одно и то же действие: возвращает соответствующий HTML-шаблон.

  • home() — главная страница;
  • about() — информация о компании;
  • contact() — контакты;
  • products() — продукция;
  • services() — услуги.

9.3 Функция vacancies()

Это более сложный маршрут, потому что он работает и как публичная страница, и как служебный интерфейс для администратора.

Режим GET

Если пользователь просто открывает страницу, происходит следующее:

  1. Из таблицы ActiveVacancy берутся все опубликованные вакансии.
  2. Из таблицы Position берутся все должности.
  3. Открывается шаблон vacancies.html.

Режим POST

Если приходит POST-запрос, значит администратор хочет добавить или удалить вакансию.

  1. Проверяется, что пользователь авторизован и является администратором.
  2. Считываются position_id и action.
  3. Если action == 'add', создается запись о вакансии.
  4. Если action == 'remove', запись удаляется.
  5. Изменения сохраняются.

10. Подробное объяснение admin-модуля

10.1 Зачем admin разделен на несколько файлов

Раньше весь внутренний раздел был в одном большом файле. Это неудобно читать и поддерживать. Сейчас логика разделена по смыслу:

  • главная страница админки;
  • отделы;
  • сотрудники;
  • должности;
  • пользователи.

10.2 admin_core.py

Файл содержит:

  • admin_bp — Blueprint админки;
  • admin_required — декоратор доступа только для администратора.

Как работает admin_required

  1. Сначала пользователь обязан быть залогинен благодаря @login_required.
  2. Потом проверяется current_user.is_admin.
  3. Если флаг ложный, вызывается ошибка 403.

10.3 admin.py

Этот файл теперь выполняет только роль точки сборки. Он импортирует все функции регистрации маршрутов и применяет их к общему admin_bp.

10.4 admin_dashboard_routes.py

Содержит одну функцию register_dashboard_routes(admin_bp).

Внутри нее объявлен маршрут /admin/index. Он считает:

  • общее число отделов;
  • общее число сотрудников;
  • число активных сотрудников.

10.5 admin_department_routes.py

Функция get_department_tree(exclude_id=None)

Формирует список вариантов для выпадающего списка родительских отделов. Это нужно в форме создания и редактирования отдела.

Маршрут departments()

Показывает только корневые отделы, то есть отделы без родителя.

Маршрут add_department()

Создает новый отдел. Важные шаги:

  • заполняет список возможных родителей;
  • проверяет, нет ли отдела с таким же названием;
  • создает новый отдел;
  • сохраняет его через commit_with_handling().

Маршрут edit_department(dept_id)

Редактирует существующий отдел. Дополнительно не дает использовать чужое уже занятое название.

Маршрут department_detail(dept_id)

Открывает страницу конкретного отдела и показывает сотрудников этого отдела.

Маршрут delete_department(dept_id)

Удаляет отдел. Благодаря связи с каскадным удалением вместе с ним удаляется и связанная структура.

10.6 admin_employee_routes.py

Функция get_position_choices()

Формирует варианты должностей для выпадающего списка в форме сотрудника.

Маршрут employees()

Показывает список всех сотрудников.

Маршрут add_employee()

Создает нового сотрудника. Проверяет уникальность email и телефона, затем сохраняет данные.

Маршрут edit_employee(emp_id)

Обновляет данные сотрудника. Тоже контролирует уникальность email и телефона.

Маршрут delete_employee(emp_id)

Удаляет сотрудника и возвращает пользователя обратно на нужную страницу.

10.7 admin_position_routes.py

Функция get_department_choices()

Возвращает список отделов для формы должности. Корневой псевдоэлемент с ID 0 исключается, потому что должность должна относиться к реальному отделу.

Маршрут positions()

Показывает все должности с привязанными отделами.

Маршрут add_position()

Создает должность. Не позволяет создать одинаковую должность в одном и том же отделе.

Маршрут edit_position(pos_id)

Редактирует должность и тоже контролирует дублирование.

Маршрут delete_position(pos_id)

Удаляет должность. Если на этой должности были сотрудники, у них обнуляется должность, а признак активности переводится в False.

10.8 admin_user_routes.py

Маршрут user_list()

Показывает всех зарегистрированных пользователей.

Маршрут delete_user(user_id)

Удаляет пользователя, но не позволяет администратору удалить самого себя из текущей сессии.

Маршрут toggle_admin(user_id)

Переключает права администратора у выбранного пользователя. Самого себя лишить прав нельзя.

11. Подробное объяснение db_utils.py

Функция commit_with_handling(...) — это единый механизм сохранения изменений в базе данных.

Что она делает

  1. Пытается выполнить db.session.commit().
  2. Если возникает ошибка SQLAlchemy, выполняет rollback().
  3. Пишет ошибку в лог.
  4. Показывает пользователю сообщение через flash.
  5. Если все успешно, при необходимости показывает сообщение об успехе.

Эта функция полезна тем, что одно и то же поведение не копируется во всех маршрутах заново.

  • кнопки перехода к продукции и вакансиям;
  • блок с краткими показателями;

12.4 templates/products.html

Страница продукции. Содержит карточки основных направлений продукции.

15. Как работает авторизация в проекте

  1. Пользователь регистрируется через /auth/register.
  2. Пароль не хранится в открытом виде, а хэшируется.
  3. После входа Flask-Login запоминает пользователя в сессии.
  4. При каждом запросе вызывается load_user(), и Flask-Login снова получает объект пользователя.
  5. В шаблонах можно использовать current_user.

16. Как работает разграничение прав

Разграничение строится на поле is_admin.

  • Если пользователь обычный, он может пользоваться публичным сайтом.
  • Если пользователь администратор, ему доступны внутренние маршруты админки.

Проверка осуществляется декоратором admin_required.

17. Как работает база данных логически

Связи между сущностями можно описать так:

  • один отдел может иметь много дочерних отделов;
  • один отдел может иметь много должностей;
  • одна должность может иметь много сотрудников;
  • одна опубликованная вакансия ссылается на одну должность.

18. Как работает тестирование

Файл tests/test_app.py создает отдельное тестовое приложение с временной базой данных SQLite в памяти. Это позволяет тестировать проект, не повреждая основную рабочую базу.

Какие тесты есть

  • доступность публичных страниц;
  • публичность страницы вакансий;
  • проверка страниц ошибок;
  • запрет доступа обычному пользователю к админке;
  • доступ администратора к админке;
  • правильное сохранение корневого отдела.

19. Как объяснить проект на защите простыми словами

Если нужно объяснить очень коротко, можно говорить так:

Проект реализован на Flask и представляет собой сайт предприятия с внутренним модулем кадрового учета. Публичная часть сайта содержит информацию о компании, продукции, услугах, контактах и вакансиях. Внутренний раздел доступен администраторам и позволяет вести структуру отделов, должностей, сотрудников и пользователей. Данные хранятся в SQLite через ORM SQLAlchemy. 22. Итог

Чтобы понимать этот проект, достаточно держать в голове простую схему:

  1. app.py запускает все приложение.
  2. models.py описывает данные.
  3. forms.py описывает ввод пользователя.
  4. auth.py отвечает за вход и регистрацию.
  5. main.py отвечает за публичный сайт завода.
  6. admin_*.py отвечают за внутренний кадровый учет.
  7. templates/ отвечают за HTML-страницы.
  8. static/ отвечает за внешний вид.
  9. tests/ проверяют, что проект работает правильно.

Если ты будешь объяснять проект именно в этой логике, то сможешь разбирать его последовательно и уверенно: от запуска приложения до конкретной страницы или функции.
